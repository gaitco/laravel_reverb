# laravel_reverb — Roadmap 0.4.0 and 0.5.0

**Date:** 2026-08-06
**Status:** Approved
**Supersedes:** nothing. Complements `docs/roadmap-0.2.0.md`, which is now fully resolved
(see "Closing the 0.2.0 deferred list").

## Goal

Close the gap between what the README admits this package cannot do and what a
**self-hosted Reverb** deployment actually needs. The package stays a Reverb client;
it does not grow toward being a general Pusher client.

## The premise, verified

The README's "is this the right package for you?" section lists three things
`pusher_reverb_flutter` supports and this package does not: encrypted channels,
Pusher's hosted service and clusters, and custom WebSocket paths. Checked against the
Reverb source (`laravel/reverb`, vendored in `~/code/domono/backend`):

| Claimed gap | Reality |
|---|---|
| Encrypted channels (`private-encrypted-`) | **Reverb does not implement them.** Zero occurrences of "encrypt" anywhere in the package. A Pusher-hosted feature, not a Reverb one. |
| Pusher hosted service / clusters | Out of scope by name and by design. |
| Custom WebSocket path | **Real defect.** `config/reverb.php:34` exposes `REVERB_SERVER_PATH`; this package hardcodes `/app/$appKey` at `lib/src/protocol.dart:68`. |

Two Reverb-native features the README does not mention and the package does not
support were found during the same pass:

- **Cache channels** — `cache-`, `private-cache-`, `presence-cache-`
  (`Channels/ChannelBroker.php:15`). A cache *hit* already works: Reverb replays the
  last event as an ordinary frame (`EventHandler.php:109`). A cache *miss* sends
  `pusher:cache_miss` (`EventHandler.php:117`), which reaches `reverb.dart:744`,
  finds no listener, and is dropped. An app cannot tell "nothing broadcast yet" from
  "still waiting".

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Positioning | Reverb-only, permanently | Two of the three "gaps" are Pusher-hosted features Reverb itself lacks. Chasing them muddies a package named `laravel_reverb`. |
| `cache_miss` delivery | Pass `pusher:`-prefixed names through `resolveEventName` literally | One line, no new API surface, and every future protocol event becomes listenable without another release. Rejected alternative: a typed `onCacheMiss` callback on `listen()` — more discoverable, but new surface serving exactly one event. |
| Release split | 0.4.0 = config + docs; 0.5.0 = refactor + observability | 0.4.0 touches only `protocol.dart` and docs, so it needs no refactor. 0.5.0 touches the connect loop three times, so the refactor pays for itself immediately. |
| `subscription_error` eviction | Won't fix — superseded | 0.3.0's `channelHealth` made the dead channel observable. Eviction would silently destroy a handle the app still holds. Flag beats delete. |

## 0.4.0 — "runs where your server actually is"

Additive. An app that changes nothing behaves identically to 0.3.0.

### 1. Custom server path

New `Reverb` constructor parameter `path`, defaulting to `''`. `buildSocketUrl`
prefixes it onto `/app/$appKey`, normalizing leading and trailing slashes so that
`ws`, `/ws` and `/ws/` all produce `/ws/app/KEY`.

Maps to Reverb's `REVERB_SERVER_PATH`. Without it, any deployment behind a reverse
proxy on a subpath cannot connect at all.

**Done when:** a `path` of `''`, `ws`, `/ws` and `/ws/` each produce the expected URL
under test, and the README's Laravel-setup section documents the env-var mapping
alongside `REVERB_HOST` and `REVERB_PORT`.

### 2. Cache channels

`resolveEventName` returns any name starting with `pusher:` unchanged, so
`channel.listen('pusher:cache_miss', ...)` reaches the existing dispatch path at
`reverb.dart:744`. No other code changes; cache hits already work.

Documented as a README recipe covering all three prefixes, stating plainly that the
hit arrives as an ordinary event and only the miss needs a listener.

**Done when:** a test proves `pusher:cache_miss` reaches a listener registered under
that exact name, and a bare `CacheMiss` still namespaces to `App\Events\CacheMiss`.

### 3. Local-dev ergonomics

Docs, plus whatever small config falls out of writing them:

- Android emulator host (`10.0.2.2`) versus iOS simulator (`localhost`)
- Cleartext `ws://` on Android API 28+ (`usesCleartextTraffic`)
- Self-signed TLS in development
- An "it works on iOS but not Android" checklist

This is where first-time users bounce, and it costs nearly nothing.

**Done when:** a developer can go from `php artisan reverb:start` to a connected
Flutter app on both simulators using only the README.

### 4. README repositioning

Rewrite "is this the right package for you?" as a scope statement rather than a
shortfall list: encrypted channels and clusters are Pusher-hosted features that Reverb
does not implement, so they are out of scope by design. `pusher_reverb_flutter` remains
the honest recommendation for anyone on Pusher's hosted service. Custom path moves off
the list entirely once item 1 ships.

## 0.5.0 — "observable and testable"

Ordered deliberately. The refactor lands first because the other two both cut across
the connect loop.

### 1. Split `lib/src/reverb.dart` (780 lines)

No API change. The file currently holds the connect/backoff loop, the channel registry,
health tracking, three separate epoch counters (`_generation`, `_generations`,
`_clientEpoch`) and app-lifecycle handling. Splitting along those seams keeps each unit
small enough to reason about, and makes the next two features edits to focused files
rather than more weight on the file most likely to grow a bug.

**Done when:** the public API is byte-identical (`exports_test.dart` unchanged), the
full suite passes untouched, and no resulting file exceeds ~300 lines.

### 2. Connection metrics

Expose ping/pong round-trip latency, reconnect count, and time since the last inbound
frame. The watchdog already tracks the last-frame timestamp, so this largely surfaces
state that exists. Lets an app render real connection quality instead of a binary dot.

**Done when:** an app can read current latency and reconnect count without reaching
into package internals, and a `fake_async` test drives latency through a simulated
ping/pong exchange.

### 3. `ReverbFake` for host-app tests

An exported in-memory implementation riding the `SocketFactory` seam this package's own
tests already use: construct it, push a frame, assert the application's callback fired —
no socket, no server, no running Reverb.

This is the largest DX gap against the competitor, and none of it is speculative
groundwork: the seam exists and is already exercised.

**Done when:** the example app ships a test that asserts a listener fires, written using
only exported API.

## Explicitly not doing

Recorded so these are decisions rather than omissions:

- **Encrypted channels** (`private-encrypted-`) — Reverb has no server-side support.
  Only pays off alongside Pusher-hosted support, which is out of scope.
- **Pusher hosted service, clusters, API-key config** — out of scope by name and design.
- **Offline event queue or replay on reconnect** — the server decides what a reconnecting
  client sees, and cache channels are Reverb's answer. Faking it client-side would invent
  delivery guarantees the protocol does not offer.
- **Evicting a channel on `pusher:subscription_error`** — superseded by `channelHealth`,
  as above.

## Closing the 0.2.0 deferred list

`docs/roadmap-0.2.0.md` is now fully accounted for: the behaviour and API items shipped
in 0.2.0 and 0.3.0, and the last open item (`subscription_error` eviction) is resolved
above as won't-fix. Its housekeeping notes stay open, none release-blocking:
`Reverb.clientVersion` is hand-synced with `pubspec.yaml`, `exports_test.dart` cannot
notice an accidental extra export, and `@visibleForTesting` on constructor parameters
is decorative.
